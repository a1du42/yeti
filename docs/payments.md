# Оплата через Heleket

Задание и уточнения пользователя от 2 ноября 2026 года: пополнение баланса в «Профиль → Оплата» (`/app?tab=payment`), все цены и суммы в долларах США (USD). Минимум 1 USD, максимум 10 000 USD включительно, шаг 0,01 USD. Комиссия на клиенте; подтверждённая переплата зачисляется в USD. Услуги, списания, выплаты и создание возвратов в это задание не входят.

## Настройка

Текущее окружение, 2 ноября 2026 года: реквизиты пользователя сохранены только в `.env.local`, публичный файл `public/heleket_f3afee8a.html` размещён и домен `a1d.by` подтверждён в кабинете Heleket. Реальный API отвечает `401 / Api not active.`; мерчант ещё не отправлен на модерацию. Heleket требует работающий сайт, активные продукты/услуги и контакты поддержки; их создание выходит за рамки этого задания. До активации `HELEKET_ENABLED=false`. После модерации включить флаг, перезапустить приложение и завершить проверку реального счёта и webhook. Секретный ключ в файл подтверждения домена не входит.

В `.env.local` заполнить серверные переменные:

```dotenv
HELEKET_MERCHANT_ID=
HELEKET_PAYMENT_KEY=
HELEKET_ENABLED=false
HELEKET_MIN_USD=1
HELEKET_MAX_USD=10000
HELEKET_FEE_PAYER=customer
```

Merchant ID и **платёжный** API-ключ берутся из настроек мерчанта Heleket. Ключ выплат не нужен. Секреты не добавлять в чат, репозиторий, URL или `NEXT_PUBLIC_*`. Реальные значения в примере отсутствуют. Пустой либо неверный комплект настроек отключает создание счетов. После настройки мерчанта включить `HELEKET_ENABLED=true` и перезапустить приложение.

`BETTER_AUTH_URL` должен содержать публичный HTTPS-origin приложения. Текущий callback: `https://a1d.by/api/payments/heleket/webhook`. Обычный и успешный возврат ведут на `https://a1d.by/app?tab=payment`. На proxy пропускать POST callback без пользовательской авторизации и без browser challenge, сохраняя защиту остальных маршрутов. Нельзя считать успешный return URL доказательством оплаты.

Применить `npm run db:migrate`, выполнить `npm run build` и перезапустить процесс приложения. Миграция `0001_worried_nuke.sql` создаёт `payment` и `payment_credit`, не изменяет существующие деньги и аккаунты. Вымышленный баланс старого стенда не переносится; баланс нового аккаунта вычисляется как сумма подтверждённых зачислений и равен 0 USD при отсутствии таких записей.

## Протокол и учёт

- Клиент отправляет сумму десятичной строкой и UUID идемпотентности. Сервер повторно проверяет диапазон, точность, сессию, подтверждение email, Origin и собственника каждого счёта. Валюта всегда задаётся сервером как USD.
- До обращения к провайдеру сохраняется идентификатор счёта. В Heleket он передаётся как `order_id`: повтор после timeout использует тот же идентификатор. Создание ограничено пятью новыми счетами в минуту на аккаунт; все пользовательские POST оплаты вместе — двадцатью запросами в минуту. Лимиты хранятся в PostgreSQL.
- Для счёта передаются `subtract=100`, `accuracy_payment_percent=0`, `is_payment_multiple=true`: комиссия на клиенте, доплата при неполной оплате разрешена. Сумму в выбранной криптовалюте и комиссию показывает Heleket перед переводом; произвольный процент комиссии в интерфейсе не обещается.
- Webhook проверяет MD5-подпись по протоколу Heleket с постоянным временем сравнения, затем сервер дополнительно получает `payment/info`. Сверяются `order_id`, UUID, исходная сумма и USD. Поддельное уведомление, недостаточная сумма, AML-проверка и простой переход на return URL не создают зачисление.
- Только финальные `paid` и `paid_over` создают зачисление. В транзакции блокируется строка счёта, записывается положительная разница с прежней подтверждённой суммой и обновляется счёт. Неизменяемые записи `payment_credit` имеют уникальную пару «счёт + подтверждённая общая сумма». Повтор webhook, ручная сверка и параллельные запросы не дублируют баланс. Более поздняя подтверждённая переплата добавляет только разницу.
- При `paid` зачисляется исходная сумма счёта. При `paid_over` превышение `payment_amount` над требуемой `payer_amount` переводится в USD через `payer_amount_exchange_rate` этого USD-счёта. Требуемая сумма включает комиссию клиента, поэтому сама комиссия не попадает на баланс. Расчёт выполняется целыми BigInt с масштабом 18 знаков, результат хранится в центах; доли цента отбрасываются. Неполные данные или аномально крупная сумма блокируют зачисление до сверки. Переплата может увеличить зачисление выше лимита 10 000 USD: лимит относится к созданию счёта.
- Timeout провайдера — 12 секунд, клиентского ожидания — 25 секунд. Отмена ожидания не отменяет счёт. Кнопки обновления истории и отдельного статуса удалены по уточнению пользователя. При повторном открытии оплаты или перезагрузке страницы загружаются актуальные данные из БД; подтверждённые статусы поступают через webhook. При неподтверждённом создании повтор запроса с той же суммой использует прежний ключ в текущей форме. При ошибке последняя полученная история и баланс сохраняются. Автоматического бесконечного polling и повторов нет.
- В истории показаны последние 50 счетов. Баланс учитывает все зачисления. Даты отображаются в часовом поясе браузера. Уведомление о новом зачислении появляется снизу по центру без переноса фокуса.

Полученные статусы возврата показываются, но автоматическое списание уже зачисленного баланса и финансовая сверка возвратов не реализованы. До отдельной задачи не инициировать возвраты оплаченных счетов через кабинет/API Heleket без ручного урегулирования баланса. AML-блокировка после зачисления также требует отдельной сверки. Устойчивой фоновой очереди нет: при отказе обработчик возвращает ошибку, восстановление возможно повторной доставкой провайдера или серверной сверкой статуса.

## Ручная проверка перед включением

Проверить границы 1 и 10 000 USD, ввод ниже/выше диапазона и вставку, пустоту, 1,01 USD и ошибку 1,001 USD; клавиатуру и обе темы при 320/768/1024 px. Без ключей кнопка недоступна с объяснением. Без сессии API не раскрывает баланс; чужой ID счёта недоступен; POST с чужим Origin запрещён.

С настроенным мерчантом: создать счёт, проверить сумму и комиссию на стороне Heleket, вернуться без оплаты — баланс не меняется. Затем подтвердить реальную оплату, проверить webhook и зачисление, повторить уведомление и ручную сверку — баланс не увеличивается повторно. Отдельно проверить переплату, недоплату, AML-проверку, недоступность провайдера и повтор после timeout. Успешная сборка и локальная имитация ответов не заменяют проверку реального провайдера.

## Выбор сервиса и уведомления

Перед оплатой требуется выбрать сервис. Сейчас предусмотрен Heleket; другие провайдеры не подключены и не имитируются. Его доступность берётся с сервера. Недоступный вариант имеет отключённое radio-поле, официальный цветной логотип и видимую подпись «Недоступен». POST создания дополнительно принимает и проверяет `provider=heleket`. Сервер ограничивает верхнюю границу 10 000 USD даже при ошибочной большей настройке окружения; текущая настройка — 10 000 USD.

Вводный текст об оплате удалён. Недоступность, ошибки загрузки и сверки показываются в общем нижнем уведомлении с предупреждающей иконкой, без переноса фокуса и без удаления последних данных. Фраза о сохранённых данных добавляется только при наличии ранее загруженного результата. Ошибки суммы и выбора сервиса остаются рядом с полями.


## Логотип и тестовый webhook — 2 ноября 2026 года

Локальный ресурс `public/assets/payments/heleket.svg` содержит официальный красный знак Heleket (#F21818) из [брендбука](https://heleket.com/ru/brand-book), источник: [официальный SVG sprite](https://heleket.com/sprites/logo.d08e0852.svg), symbol brandmark-red. Геометрия и цвет сохранены; заменена только внешняя обёртка symbol на самостоятельный SVG. В приложении логотип не перекрашивается, не обесцвечивается и не теряет opacity при недоступности. Название и статус видимы рядом, изображение декоративно для скринридера.

По выбору пользователя проверяется официальный [test-webhook/payment](https://doc.heleket.com/ru/methods/payments/testing-webhook) без денег. Отдельный callback `/api/payments/heleket/test-webhook?probe=<uuid>` проверяет подпись платёжным API-ключом и ожидаемые type=payment, currency=ETH, network=eth, status=paid. Это синтетические данные официального примера, не расчёт цены. Обработчик не обращается к payment и payment_credit и не зачисляет деньги. Он работает только при заранее созданной сервером записи verification с identifier=heleket-webhook-probe, id=probe, value=pending и сроком действия; при успехе сохраняет только время, статус и факт проверки подписи. Повтор не меняет результат, неизвестная/истёкшая проверка отклоняется. Для ручного запуска создаётся одноразовая запись на 10 минут, её UUID передаётся в callback URL подписанного POST к `/v1/test-webhook/payment`, после проверки запись удаляется. UUID является идентификатором проверки; авторизация обеспечивается подписью. Секретный ключ в URL не передаётся.

Фактический результат обращения к Heleket: HTTP 401, Api not active. Тестовое уведомление из Heleket не отправлено; необходима активация API мерчанта. Приём реальных платежей оставлен выключенным. Разовая локальная отправка подписанного сообщения через публичный HTTPS callback проверила нашу сторону: корректная подпись → 200, поддельная → 403, повтор → 200 без изменения результата; журнал зачислений не изменился. Это не подтверждение доставки из Heleket. Одноразовая запись удалена, постоянных тестовых скриптов и фреймворков не добавлено.
