# Контракты компонентов

При нажатии на вкладку мышью или касанием не показывать внешнюю прямоугольную рамку фокуса. Активность сохраняет цвет и нижний индикатор. При управлении клавиатурой видимое кольцо фокуса обязательно; не снимать DOM-фокус и не отключать outline для всех способов ввода.

Все компоненты используют [токены](../../tokens.css) и правила [анимации](motion.md). Это контракты; соответствующие примитивы приложения строятся на Radix UI и CSS Modules согласно [выбранному стеку](../development.md). Не создавать параллельную систему компонентов, собственные focus trap и keyboard navigation без необходимости.

## Общие состояния

| Состояние | Требование |
| --- | --- |
| Default | Видимая подпись, понятная граница действия |
| Hover | Работает только при поддержке hover, не открывает единственный путь к действию |
| Focus | Мгновенное кольцо; не меняет размеры |
| Pressed | Немедленная обратная связь, transform не двигает соседей |
| Disabled | Настоящая недоступность действия, нейтральные токены, понятная причина рядом |
| Loading | aria-busy, сохранённая геометрия, защита от повторной отправки |
| Error | Конкретная ошибка и восстановление рядом с источником |
| Success | Подтверждённый результат и уведомление снизу по центру; одна live region |

Применимость указывать по смыслу: у навигационной ссылки нет вымышленного success, у заголовка нет loading. Дополнительно нужны selected, expanded и read-only там, где это реальные состояния.

## Кнопки и ссылки

Высота от 44 px, отступы 16 px по горизонтали, gap 8 px, радиус 8 px. Одна основная кнопка на рабочую область. Основная: action / action-text с action-border 1 px. Вторичная: surface / text с control-border. Текстовая: link, без слабой границы «на всякий случай».

Hover меняет фон через короткий opacity-слой либо мгновенно; pressed масштаб 0,98 до 160 мс. Не добавлять hover-подъём всем строкам и карточкам. Focus не зависит от hover. Disabled использует muted и text-secondary вместо opacity всего элемента; не позволяет действие и не требует наведения для объяснения.

В загрузке сохранять ширину, например «Сохранить» → «Сохраняем…». Статический индикатор и подпись достаточны; бесконечный spinner не обязателен. Ссылка выполняет переход, button выполняет действие. Действия «Сохранить», «Отмена», «Закрыть» обычно без иконок; «Скопировать», «Скачать», «Добавить» могут иметь одну иконку.

## Поля и группы

Label над полем, gap 8 px, высота от 44 px. Border 1 px во всех состояниях. Placeholder только пример формата. Поле не заменяет label. Связать ошибку через aria-describedby и aria-invalid, обязательность обозначить текстом или знаком с пояснением.

Проверять впервые по blur или submit, затем перепроверять исправляемое поле. При неудаче сохранить введённое. Для нескольких ошибок дать фокусируемое резюме со ссылками на поля; иначе сфокусировать первое ошибочное поле. Не блокировать отправку без объяснения причины.

Справочные объяснения группы находятся у `?` рядом с её названием. Единицы, ограничения допустимого ввода, цена и ошибка остаются видимыми: это данные и условия, не скрытая справка. Read-only позволяет чтение и копирование, отличается от disabled.

### Выбор элемента

| Элемент | Когда выбирать | Контракт |
| --- | --- | --- |
| Checkbox | Независимый выбор да/нет или несколько совместимых вариантов | Нативный `input type=checkbox`; подпись рядом, нажимается вся строка высотой от 44 px. Группу объединять `fieldset` и `legend`. Не делать взаимоисключающие checkbox вместо radio. Для немедленного включения настройки использовать switch; для выбора в форме — checkbox |
| Radio | Один вариант из короткого списка, который полезно видеть целиком | Нативные `input type=radio` с общим `name`, отдельными label и общим `fieldset`/`legend`. Обязательность относится ко всей группе. Не выбирать значение заранее, если нужен осознанный выбор; оправданное значение по умолчанию допускается |
| Select | Один вариант из более длинного заранее известного списка | Нативный `select` с label; для обязательного выбора без начального значения — пустой option «Выберите …» с `value=""`. Выбор не отправляет форму и не выполняет переход. Для поиска по большому списку понадобится отдельная спецификация combobox |
| Textarea | Свободный многострочный текст | Нативный `textarea`, label, видимое ограничение длины при его наличии. Сохранять переносы, разрешать увеличение высоты вручную; не менять высоту анимацией. Счётчик не объявляет каждый символ через live region |
| Числовое поле с единицей | Измеримая величина, для которой осмысленны увеличение и уменьшение | Нативный `input type=number`, подходящий `inputmode`, утверждённые `min`/`max`/`step`. Единица видна рядом и входит в label; повторный декоративный суффикс скрыт через `aria-hidden`. Для идентификаторов, телефонов и значений с ведущими нулями нужен текстовый input |
| Read-only | Значение нельзя менять здесь, но нужно прочитать или скопировать | `readonly` у input/textarea, видимая пометка «только чтение» и причина рядом. Поле остаётся в порядке Tab, допускает выделение и копирование. У select/checkbox/radio нет нативного readonly: показывать подписанное текстовое значение вместо имитации |

### Подписи, ограничения и ошибки

Label над текстовым, числовым полем и select; у checkbox/radio — рядом. Legend называет группу, отдельные label — варианты. Обязательность или необязательность видна до ввода. Подсказки с форматом, единицей, диапазоном и лимитом длины связаны через `aria-describedby` вместе с идентификатором ошибки. Ограничения берутся из подтверждённой модели; числа на стенде не становятся правилами услуг.

Проверять впервые при выходе из поля либо отправке, затем при исправлении. Для radio переход между вариантами внутри группы не считается выходом. Ошибку группы показывать один раз, связывая её со всеми radio и их `aria-invalid`. Ошибка объясняет исправление словами, а не только рамкой или цветом. При нескольких ошибках отправки фокус получает резюме со ссылками на поля; при одной — само поле. Исправление обновляет резюме без переноса фокуса.

Не обрезать вставленный текст молча. При превышении лимита сохранять ввод, показывать счётчик и ошибку до исправления; принятый способ подсчёта должен совпадать с серверным. В локальном примере лимит 240 считается через JavaScript `value.length` (кодовые единицы UTF-16; некоторые символы занимают две), это не утверждение продуктового формата. В обязательном числовом поле различать пустое значение, неверный ввод, выход за диапазон и нарушение шага. Не округлять дроби и не подменять пустоту нулём. Ошибка сохраняет единицу и допустимые условия.

Если у числового поля заданы границы «от» и «до», ввод вне диапазона невозможен: при вводе с клавиатуры, вставке и изменении стрелками число ниже минимума сразу заменяется минимумом, выше максимума — максимумом. Обе границы включены. Диапазон и поведение видны рядом с полем; одних min/max недостаточно. Поле можно очистить для нового ввода; пустота не считается нулём. Проверка шага сохраняется, дроби не округлять автоматически. В будущей реализации сервер повторно проверяет диапазон.

Disabled означает реальную недоступность, исключает редактирование и обычный порядок Tab; причина видна рядом. Read-only сохраняет чтение и копирование. Не заменять readonly на disabled ради похожего оформления. В будущей реализации ограничения и права повторно проверяются сервером; readonly не защищает данные от изменения запроса.

### Длинные значения и адаптивность

Подписи, варианты checkbox/radio, подсказки и ошибки переносятся без обрезки. Контейнеры и поля имеют `min-width: 0`, поле занимает доступную ширину. Textarea переносит длинные ссылки через `overflow-wrap: anywhere`; высота может увеличиваться вручную. Однострочный input прокручивает значение внутри при перемещении каретки; для длинного read-only значения, которое нужно видеть целиком, выбирать textarea.

Нативный select может обрезать выбранный текст и по-разному показывать список в браузерах. Полное выбранное значение выводить ниже с переносом, если длина мешает его прочитать; не полагаться на `title`. Подписи вариантов делать различимыми с первых слов. На стенде полное выбранное значение всегда повторяется под select. Не заменять системный список собственным меню только ради внешнего вида.

### Клавиатура

- Tab / Shift+Tab перемещают фокус; видимое кольцо не меняет геометрию. Checkbox переключается Space; нажимается и его label.
- Radio: Tab входит и выходит из группы, стрелки перемещают выбор, Space отмечает вариант. При отсутствии выбора начальная точка входа может отличаться по браузеру и направлению обхода. Использовать нативное поведение без собственного перехвата стрелок.
- Select: нативные стрелки и поиск по буквам; открытие и подтверждение зависят от системы и браузера. Не перехватывать системные сочетания.
- Textarea: Enter добавляет строку, Tab переходит дальше; не отправлять форму по обычному Enter.
- Number: стрелки вверх/вниз меняют значение на step; доступен обычный ввод. Read-only: Tab, выделение и Ctrl+A / Ctrl+C работают; ввод не меняет значение.

Интерактивный образец: раздел «Набор полей» в [витрине](../../design-system.html#field-set). Выбор, ошибки и reset локальны; API и сохранения нет.

## SectionHelp: знак `?`

Единый компонент для разделов и смысловых групп. Контракт: `label` (название раздела), `content` (краткое пояснение), устойчивый идентификатор связи; привязка к заголовку без вложения button внутрь ссылки.

- Визуальный знак 18 px, активная область 44 × 44 px; расстояние от названия 4-8 px с учётом реальных hit areas.
- Ширина тултипа до 320 px, на узком экране до ширины viewport минус 32 px; padding 12 px, радиус 8 px, текст 14/20 px.
- Токены help-bg / help-text / help-border; размещение сверху или снизу с автоматическим переворотом у края и отступом 8 px.
- Hover: задержка 240 мс, появление 240 мс. Focus: без задержки. Click, Enter, Space и tap открывают/закрывают справку без задержки.
- Escape закрывает; фокус остаётся на кнопке. Уход с кнопки на текст тултипа не закрывает его. Нет автозакрытия по таймеру.
- На touch закрытие повторным tap, касанием вне области или Escape с внешней клавиатуры. Одновременно открыт один тултип.
- Обычная справка не содержит ссылок и кнопок, не получает фокус: `role=tooltip`, триггер `aria-describedby`, доступное имя «Пояснение к разделу „Заказы“».
- Отложенные обработчики отменяются при уходе, переключении, unmount. Закрытая справка не остаётся интерактивным невидимым слоем.

Для длинной интерактивной инструкции нужен отдельный экран помощи или немодальная панель с корректной семантикой. Не выдавать такую панель за tooltip. Готовые тексты: [content.md](content.md).

## Навигация и вкладки

На телефоне 320–767 CSS px основные переходы рабочих зон постоянно находятся внизу. Нижнее меню: 3–5 равных пунктов, Phosphor Regular 20 px над видимой подписью, высота от `--size-bottom-nav` (72 px) плюс safe area, область нажатия не меньше 44 × 44 px. Активная ссылка использует `aria-current="page"`, selected-фон и selected-текст, без изменения размеров или веса. Это nav со ссылками, не ARIA tabs. Контент, фокус, уведомления и закреплённые действия не перекрываются панелью. В «Ещё» размещать вторичные переходы текущей зоны и аккаунт; верхний аккаунт может оставаться быстрым доступом. Полный контракт, адаптация клавиатуры и образец — [mobile.md](mobile.md).

Sidebar: текущая ссылка имеет selected-фон, вес 500 и aria-current=page. Иконка 20 px + подпись. Переходы между маршрутами являются ссылками. Избранная зона не открывает навигацию других зон автоматически.

Вкладки для содержимого одного экрана: role tablist/tab/tabpanel, aria-selected, стрелки и Home/End. При дорогой подгрузке ручная активация Enter/Space; при мгновенной локальной смене допустима автоматическая. Не выдавать навигационные ссылки за ARIA tabs.

Группа вкладок всегда занимает 100% доступной ширины своего контейнера. Вкладки делят ширину поровну (`flex: 1 1 0; min-width: 0`), содержимое выравнивается по центру. Каждая вкладка обязательно содержит иконку Phosphor Regular 20 px и видимую текстовую подпись с промежутком 8 px. Иконка декоративная (`aria-hidden="true"`), доступное имя задаёт подпись. Активная линия занимает всю ширину вкладки.

Правило действует во всех темах и на всех ширинах. Исключение для авторизации: иконка и полная подпись всегда рядом в одну строку (включая 320 CSS px), без вертикального размещения и переноса текста; подробности — [auth.md](auth.md#компоновка-и-доступность). В остальных группах на узком экране разрешать перенос длинных подписей, сохраняя иконки, равные доли ширины и высоту области нажатия не менее 44 px. Не заменять вкладки select или меню и не обрезать названия ради размещения. Сохранять выбранный раздел и фильтры в URL, если это полезно для возврата и обмена ссылкой; секреты в URL исключены.

## Списки, таблицы и статусы

Настоящая table для сравнения по колонкам, список для самостоятельных объектов. Строка не ниже 52 px, padding 12-16 px; суммы выровнены вправо. Не делать всю строку кнопкой с вложенными кнопками: название содержит ссылку, действия вынесены отдельно.

Управление сортировкой размещать справа над таблицей: кнопка-иконка с доступным именем открывает выбор колонки и направления. Заголовок выбранной колонки получает aria-sort; фильтры имеют подписи. Пагинация или серверное окно ограничивают объём. Виртуализация применяется после измерения и проверки доступности, а не по произвольному количеству строк.

Статус: обязательная иконка Phosphor Regular, короткая подпись и семантический цвет. Не добавлять декоративную точку каждому пункту. Последнее обновление показывать, когда от свежести зависит решение.

Мобильный список оставляет название, статус, основной параметр и действие. Остальное доступно в деталях. Если сравнение требует настоящей широкой таблицы, разрешён явно подписанный локальный горизонтальный скролл с клавиатурой; страница в целом не скроллится по горизонтали.

## Диалог и боковая панель

Диалог до 512 px, padding 24 px (16 px на узком экране), радиус 16 px. Для самостоятельной большой формы открывать страницу. Панель до 448 px, на узком экране занимает доступную ширину.

Заголовок, при необходимости краткое описание, содержимое, действия. Фокус внутри, фон inert, видимая кнопка закрытия, Escape, возврат фокуса к триггеру. Начальный фокус по контексту: заголовок длинного текста или безопасное действие подтверждения. Не фокусировать разрушительное действие автоматически.

Открытие и закрытие модального окна не сдвигает фон при исчезновении полосы прокрутки. Заранее резервировать её место на корневом элементе страницы: `html { scrollbar-gutter: stable; }`. Это правило действует постоянно, а не включается после открытия окна; блокировку прокрутки фона при этом сохранять. Проверять неизменность ширины и горизонтального положения контента, шапки и боковой навигации, а также сохранение позиции прокрутки после закрытия. Не компенсировать сдвиг анимацией или фиксированным отступом 15/17 px: ширина полосы зависит от системы и масштаба. При выборе будущей библиотеки модальных окон исключить двойную компенсацию через её scroll lock и общий CSS. Для старых целевых браузеров без `scrollbar-gutter` предусмотреть отдельное проверенное решение после определения их поддержки; в современных браузерах витрины используется нативное резервирование. Наложенная системная полоса прокрутки не требует дополнительного зазора.

При несохранённых изменениях предложить сохранить или закрыть с потерей изменений. Не закрывать критичный процесс неявным нажатием на backdrop. Необратимое действие поясняет конкретный объект и последствия. Обратимое изменение может предлагать отмену только если backend действительно умеет её выполнить.

## Обратная связь

- Skeleton повторяет структуру и резервирует место. По умолчанию статический, без shimmer. При обновлении оставлять текущие данные и пометку обновления.
- Empty state: «Заказов пока нет» + одно действие «Выбрать услугу». Пустой поиск: «Ничего не найдено» + «Сбросить фильтры».
- Ошибка загрузки занимает сломавшийся блок и содержит «Повторить». Успешно загруженные блоки не исчезают.
- Временное уведомление не крадёт фокус, использует status/aria-live=polite. Не дублировать каждое сообщение несколькими live regions.
- Ошибки, требующие действия, не исчезают автоматически. Обычное уведомление может закрыться через 5 с с паузой на hover/focus; время чтения не является длительностью анимации.
- Графики добавлять только для утверждённых данных; подписи, единицы, легенда и табличная альтернатива обязательны. Значения доступны касанием и клавиатурой, не только наведением.

## Стабильность переключения вкладок

Переход между любыми вкладками плавный: одновременное исчезновение прежней панели и появление новой за 440 мс, без задержки действия; при reduced motion только opacity до 100 мс. Вес шрифта, размер, межстрочный интервал, отступы и границы названий одинаковы во всех состояниях, чтобы текст не дёргался. Активность показывают цвет и плавное появление индикатора. Повторные переключения прерывают текущий переход; доступность и фокус обновляются сразу.

В статической витрине панели занимают одну ячейку CSS Grid: высота определяется самой высокой панелью, не меняется при переключении. Неактивная панель сразу получает inert и aria-hidden; после затухания скрывается через visibility. Не анимировать размеры контейнера.

## Обязательное оформление обратной связи и таблиц

- Каждый статус обязательно содержит иконку Phosphor Regular и видимую текстовую подпись; цвет дополняет смысл. Декоративная иконка скрыта от скринридера.
- Уведомления об успешном сохранении и завершении действия появляются снизу по центру экрана, относительно viewport, с учётом safe area. Показывать только подтверждённый результат, не красть фокус; role=status. Ошибки ввода показывать рядом с полями, не заменять их toast.
- Все кнопки действий в таблице размещать справа, в последнем столбце «Действия», и показывать только иконками. Обязательны доступное имя с действием и объектом, видимый фокус и область нажатия минимум 44 × 44 px. На узком экране действия также остаются справа. Общие кнопки таблицы располагаются справа над ней и тоже используют иконки.

Toast появляется через opacity и смещение снизу на 8 px за 440 мс; reduced motion — только opacity до 100 мс. Центрирование не должно сбиваться во время анимации. В таблице иконки не заменяют текстовые статусы.

## Кнопка и навигация аккаунта

Аккаунт располагается внизу sidebar, на узком экране — в шапке. Кнопка имеет aria-expanded и aria-controls, область нажатия не меньше 44 × 44 px. Раскрываемая навигация содержит сведения аккаунта и ссылки «Оплата» / «Настройки» с Phosphor Regular и текстом. Полные имя и email доступны в раскрытом блоке даже при компактном триггере. Не использовать ARIA menu без реализации его контракта: для двух переходов достаточно nav со ссылками. Под ссылками расположен красный пункт-кнопка «Выйти» с иконкой SignOut Regular. Tab проходит ссылки и кнопку; стрелки и Home/End помогают перемещаться по всем трём пунктам, Escape закрывает с возвратом фокуса. Клик вне, уход фокуса и выбор ссылки закрывают блок. При выборе фокус переносится к заголовку аккаунта. Меню не блокирует фоновую прокрутку.

Вкладки аккаунта следуют общему контракту. Несколько независимых tablist не меняют выбор друг друга. Зелёный щит в демонстрации оплаты не является доказательством безопасности; рядом виден текст, что списания нет. Условия реальной оплаты и подтверждения сервера определяются отдельно.


В шапке всплывающего окна аккаунта, отдельно от навигационных пунктов, расположен компактный выбор темы: Desktop / Sun / Moon (Phosphor Regular). Постоянных текстовых подписей нет; у каждой кнопки есть доступное имя, tooltip по наведению/фокусу/касанию и aria-pressed, ровно одна тема выбрана. Область нажатия не меньше 44 × 44 px. В списке остаются «Настройки» → «Оплата» → разделитель → красный «Выйти». Tab проходит три кнопки и ссылки; стрелки вверх/вниз и Home/End перемещают фокус. Выбор темы не закрывает окно; настройка сохраняется, системная тема работает как прежде. Отдельной строки «Оформление» и select нет.

## Поля и кнопки форм доступа

Специальный контракт [auth.md](auth.md) уточняет общие правила: имя обязательно в обычной регистрации; сервисы показываются только во входе и автоматически создают аккаунт при первом успешном входе. Остальные требования: пометки обязательности не показываются, required сохраняется. Пароль и повтор проверяются на совпадение при регистрации и восстановлении; видимость каждого поля управляется отдельным глазом Phosphor с aria-pressed. Часовой пояс при регистрации выбирается вручную только при неудаче определения браузером. Брендовые кнопки — только цветные знаки с доступным именем, tooltip и областью ≥44 × 44 px; до четырёх равных кнопок в ряд. Видимость задают публичные признаки серверной конфигурации. Это не меняет требования к подписям обычных вкладок: иконка и видимый текст обязательны.
