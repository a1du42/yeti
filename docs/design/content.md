# Тексты интерфейса и справка

## Голос

Писать по-русски, спокойно и прямо. Формулировка начинается с действия или понятного состояния. Обращение на «вы» без заглавной буквы. Не описывать реализацию, должности, внутренние права и устройство организации там, где человек хочет выполнить задачу.

Одно намерение имеет одно название: «Выбрать услугу», «Открыть заказ», «Сохранить», «Скопировать ссылку», «Повторить». Не чередовать «Применить», «Готово» и «ОК» для одного сохранения. «Продолжить» уместно только между этапами, где действие ещё не завершает оформление.

## Правило справки

Справочные пояснения находятся в тултипе по знаку `?` около названия раздела или смысловой группы. Не расставлять `?` у каждой строки: добавлять только при наличии полезного объяснения. Название и знак остаются рядом при переносе; hit area не накрывает соседний control.

Формула: **что сделать → что будет видно / какой результат получить**. Обычно одно-два предложения, 12-35 слов. Не повторять заголовок другими словами. Не обещать функцию, которая не подтверждена. Все тексты ниже являются примерами для соответствующего будущего сценария, а не обещанием его реализации.

В тултипах не упоминать категории людей: «администратор», «пользователь», «партнёр», «менеджер», «оператор», «роль». Не писать «для кого создан раздел». Например, вместо «Панель для администратора» писать «Найдите заказ и откройте его, чтобы проверить параметры и последние изменения».

Правило действует и в `/admin`, и в `/partners`: название самого раздела может отражать предмет работы, но его пояснение обращается к действию. Разделение доступа описано в технической документации и реализуется на сервере.

## Примеры готовых тултипов

| Раздел / группа | Текст справки |
| --- | --- |
| Обзор | Проверьте состояние заказов и откройте нужный, чтобы посмотреть подробности или доступные действия. |
| Услуги | Выберите услугу и откройте настройки. Перед оформлением проверьте параметры и итоговую стоимость. |
| Заказы | Найдите нужный заказ по названию или статусу. Откройте его, чтобы проверить параметры и историю изменений. |
| Канал | Укажите ссылку на канал, для которого оформляете услугу. Перед продолжением проверьте, что выбрали нужный канал. |
| Параметры заказа | Задайте нужные значения. Проверьте обновлённый расчёт перед подтверждением заказа. |
| История | Посмотрите, как менялось состояние заказа. Последнее событие помогает понять, что произошло после вашего действия. |
| Операции | Выберите период и откройте запись, чтобы проверить сумму и состояние операции. |
| Уведомления | Выберите события, о которых хотите узнавать, и сохраните изменения. |
| Ссылки | Скопируйте ссылку и поделитесь ею. Здесь можно проверить связанные с ней приглашения. |
| Приглашения | Выберите период, чтобы посмотреть приглашения и связанные с ними события. |
| Начисления | Откройте запись, чтобы посмотреть основание начисления, сумму и текущее состояние. |
| Выплаты | Проверьте доступную сумму и условия. Если выплата доступна, укажите реквизиты и подтвердите запрос. |
| Каталог | Откройте услугу, измените нужные параметры и проверьте их перед сохранением. |
| Учётные записи | Найдите нужную запись и откройте её, чтобы проверить сведения и доступные действия. |
| Журнал | Выберите период и тип события, чтобы найти изменения и посмотреть их результат. |

Проверить соответствие реальной функции перед использованием. Например, строка «История» не подходит услуге, источник которой не предоставляет события. Для нового раздела сначала описать действие, затем составить текст по этому же принципу.

## Что не прятать в тултип

Цена и валюта, комиссия, начало отсчёта, доступность отмены, необратимость действия, срок оплаты, ошибки полей, состояние соединения и факт сохранения остаются на экране. Правила программы должны быть доступны отдельным понятным документом. Обязательное предупреждение нельзя заменить знаком `?`.

Label, единицы измерения и допустимые диапазоны являются частью поля. Accessible name кнопки без текста не является тултипом. Для длинного обрезанного значения предпочтительны перенос или раскрытие, а не ещё один скрытый tooltip. У графика точные значения являются данными, а справка о графике размещается у его заголовка.

## Словарь состояний

| Смысл | Текст |
| --- | --- |
| Запрос выполняется | «Сохраняем…», «Обновляем…», «Проверяем состояние…» |
| Подтверждённый результат | «Изменения сохранены», «Ссылка скопирована» |
| Нет объектов | «Заказов пока нет» |
| Нет совпадений | «По этим условиям ничего не найдено» |
| Сбой получения | «Не удалось загрузить заказы. Повторите попытку» |
| Соединение потеряно | «Нет соединения. Показаны последние загруженные данные» |
| Отправка с неизвестным исходом | «Ответ пока не получен. Проверяем состояние операции» |
| Конфликт редактирования | «Данные изменились. Обновите их перед сохранением» |
| Недоступность действия | «Сейчас это действие недоступно» + известная конкретная причина |

Не называть timeout «Платёж отклонён» и отсутствие ответа «Заказ отменён». Известную причину ошибки назвать, неизвестную не выдумывать. Сообщение объясняет следующий шаг; технический идентификатор можно дать отдельно для обращения, без stack trace.

## Форматирование

Даты, время, числа и деньги форматируются по локали. Часовой пояс показывается там, где влияет на сроки. Для документации дата фиксирована; интерфейс не должен навсегда считать Europe/Moscow часовым поясом всех людей. Валюта всех цен и денежных сумм — USD; показывать код USD и два знака после запятой.

Не использовать искусственные метрики, отзывы и проценты. Примеры с данными явно подписывать «Пример» или «Демонстрационные данные». Не писать «мгновенно», «без блокировок», «100% безопасно» и другие непроверенные гарантии.

## Проверка текста перед сдачей

Прочитать каждый заголовок, tooltip, кнопку, ошибку и пустое состояние глазами человека, выполняющего задачу. Проверить: понятное действие; отсутствие ролей в справке; отсутствие технического жаргона; соответствие фактической функции; короткая подпись; доступность критических условий без открытия tooltip.

## Подтверждение действий

Формы доступа используют отдельный [словарь сценариев](auth.md#сценарии): «Войти», «Создать аккаунт», «Не помню пароль», «Отправить ссылку», «Сохранить пароль», «Вернуться ко входу». Email не обязателен при входе через сервис. Общие ответы входа и восстановления не раскрывают наличие аккаунта; никакой пароль сервиса не запрашивается в форме YETI STREAM. В документационной витрине результаты явно названы демонстрационными.

«Изменения сохранены» и «Ссылка скопирована» показываются уведомлением снизу по центру после подтверждения результата. Ошибку «Укажите полную ссылку» показывать у поля. Названия кнопок-иконок таблицы включают объект: «Скопировать название: Пример 01».

В регистрации часовой пояс показывать понятным названием города или региона и текущим смещением: «Часовой пояс: Москва · UTC+03:00. Определён автоматически». При неудаче: «Не удалось определить часовой пояс. Выберите его из списка». В ручном выборе повторять полную подпись под select; IANA-код может дополнять одинаковые названия, но не заменяет понятное название.

В формах доступа подписи: «Пароль», «Повторите пароль», «Новый пароль», «Повторите новый пароль», «Часовой пояс». Не добавлять «обязательно» и звёздочки. Для глаз использовать доступные имена «Показать пароль» / «Скрыть пароль», для повтора — «Показать повтор пароля» / «Скрыть повтор пароля». Кнопки сервисов не имеют видимой текстовой подписи; доступное имя и tooltip — «Продолжить через Google» и аналогично для остальных. Ошибка повтора: «Пароли не совпадают. Повторите пароль ещё раз».

Обычная регистрация содержит подпись «Имя» и ошибку «Введите имя». Во входе перед сервисами не показывать пояснение об автоматическом создании аккаунта. В регистрации сервисы не показываются. Демонстрационный результат различает первое создание и повторный вход; реальное создание подтверждается сервером.

После вкладок показывать заголовок панели: «Быстрый старт» во входе и «Создать аккаунт» в регистрации. Затем во входе — сервисы (или поля, если сервисов нет), в регистрации — поле «Имя». Подписи вкладок и кнопок действий сохранять.
