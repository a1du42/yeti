## Формы доступа — 2 ноября 2026 года

Добавлены [инструкция](auth.md) и раздел [#auth](../../design-system.html#auth): Google / YouTube, Яндекс ID, Telegram, Kick, email и пароль; регистрация, подтверждение почты, восстановление и новый пароль. Это документация: реальные OAuth, письма и сессии отсутствуют. Приложение, зависимости, автотесты и постоянные проверочные скрипты не добавлялись.

Фактически проверено вручную в Chrome на http://127.0.0.1:100/#auth:

- Пустой вход показывает две ошибки и фокусирует резюме; ссылка переводит к email. Исправление полей снимает ошибки; «Показать» раскрывает вымышленный пароль. Отказ входа и ошибка соединения дают понятный результат без потери ввода; повтор с успешным сценарием завершает демо-вход.
- Регистрация: короткий пароль даёт ошибку у поля; длинная вымышленная фраза позволяет получить общий ответ о письме и выполнить локальное подтверждение адреса.
- Восстановление: запрос для вымышленного неизвестного адреса показывает общий ответ, демонстрационная недействительная ссылка даёт ошибку с предложением запросить новую. Повтор с успешным сценарием открывает форму нового пароля; сохранение показывает демо-результат и позволяет вернуться ко входу. Настоящие учётные данные не менялись.
- Google / YouTube, Яндекс и Kick проверены до локального успеха без запроса email; Telegram — до отмены. Переключение вкладки во время ожидания отменяет ответ. «Отменить ожидание» возвращает фокус на исходную кнопку и сохраняет форму. Сброс очищает все шесть полей, ошибки, результаты и режим показа паролей.
- ArrowRight и End выбирают регистрацию и восстановление. Общий CSS сохраняет равную ширину вкладок (около 148,9 px на desktop); иконки и подписи видимы. С локальным «Уменьшить движение» computed transition панели — 0,1 с, без перемещения.
- Светлая тема визуально просмотрена на фактических 320 CSS px (clientWidth = scrollWidth = 308 px с резервом полосы прокрутки); тёмная — на 320 px и desktop. Вкладки переносят подписи. Разовые измерения на 376 / 415 / 768 / 1024 / 1440 CSS px не выявили горизонтального переполнения. Запрошенные 375 / 414 округлились из-за масштаба браузера. Временный viewport снят, системная тема и обычное движение восстановлены, демо-данные очищены.
- Console errors отсутствуют. Проверка синтаксиса showcase.js, уникальности HTML id, label/ARIA-связей, локальных ресурсов, Markdown-путей, определённости CSS-переменных и git diff --check без ошибок. Два виртуальных якоря account-payment/account-settings обрабатываются существующим JavaScript. Цвета не менялись: контраст текста основной кнопки 4,55:1; текстов ошибок на error-поверхности 5,09:1 / 6,74:1; остальные общие пары в таблице ниже.

[Снимок витрины](auth-preview.png). Не проверены отдельно: screen reader, физическое touch-устройство, zoom 200%, системное переключение reduced motion, полный сценарий на каждой ширине и открытие новых форм через file://. Добавлены локальные примеры checkbox, radio, select, textarea, числового поля с единицей и read-only; расширены контракты и инструкция просмотра. Приложение, зависимости и автотесты не создавались.

Фактически проверено в Chrome на http://127.0.0.1:100/:

- Пустая отправка: три сообщения, резюме ошибок получает фокус, ссылки переводят к соответствующим полям. При одной ошибке фокус получает поле. Повторный переход из поля к ссылке другой ошибки работает; неизменившееся резюме не пересоздаёт ссылки при blur.
- Checkbox переключается Space; radio — стрелкой; select — стрелкой и выбором длинного варианта. Tab / Shift+Tab между select и textarea, видимый фокус и полная подпись выбранного значения подтверждены.

- Read-only допускает выделение и копирование всей ссылки через Ctrl+A / Ctrl+C; ввод не меняет значение. Нативный readonly подтверждён в DOM.
- Сброс очищает значения, выбранные варианты, ошибки и резюме; счётчик возвращается к 0, подпись выбранного select скрывается. Исправлена обнаруженная рассинхронизация: подписи обновляются после нативного reset.
- Ручной визуальный просмотр светлой и тёмной темы при фактической ширине 320 CSS px: подписи переносятся, длинное значение textarea не переполняет поле, кольцо фокуса видно. Проверка геометрии при фактических ширинах 376 / 415 / 768 / 1024 / 1440 CSS px не выявила горизонтального переполнения. Из-за текущего масштаба браузера запрошенные 375 / 414 округлились до 376 / 415. Временное ограничение viewport снято, восстановлена светлая тема.
- С локальным «Уменьшить движение» ошибки и фокус обновляются сразу; уведомление использует существующий reduced motion путь. Проверка консоли не показала ошибок JavaScript.
- Разовые проверки: синтаксис showcase.js через node --check; уникальность HTML ID, цели label/ARIA/якорей, существование файлов по Markdown-ссылкам, определения CSS-токенов и git diff --check. Ошибок нет. Контраст вторичного текста на поверхности: 5,09:1 / 8,09:1; ошибок: 5,55:1 / 9,22:1; границы поля: 3,86:1 / 4,84:1 (светлая / тёмная).

Не проверялись отдельно: screen reader, сенсорное устройство, zoom 200%, открытие новых примеров через file:// и системное переключение reduced motion. Чек-лист полного просмотра остаётся в [showcase.md](showcase.md#набор-полей); это отчёт только о документационной витрине.

## Проверка документационного комплекта

Проверить локальные Markdown-ссылки и пути изображений; каждую var-ссылку в CSS; отсутствие превышений motion-лимита в нормативных правилах; согласованность тем и названий токенов; актуальность списка открытых вопросов. Проверить, что не добавлены зависимости, приложение и автотесты.

Hallmark self-critique для спецификации: Philosophy 4, Hierarchy 4, Execution 4, Specificity 5, Restraint 5, Variety 4. Это качественная самопроверка документа, а не измерение работающего интерфейса. Неприменимые к документации проверки hero, реальной навигации и browser responsiveness не отмечаются пройденными.
