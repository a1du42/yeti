# Движение и обратная связь

Цель движения: показать нажатие, изменение состояния или появление контекстного слоя. Анимация не является отдельным аттракционом. Три семейства покрывают систему: press, fade, небольшой slide/scale для overlay.

## Жёсткие ограничения

- Любой конечный переход от действия до итогового визуального состояния занимает не более **800 мс**, включая задержки и цепочки. Если exit 240 мс и enter 320 мс идут последовательно, общий срок 560 мс.
- Начало обратной связи о нажатии немедленное, не позднее 100 мс. Не ждать завершения движения для запроса, навигации, обновления фокуса или объявления ошибки.
- 800 мс не является лимитом сетевой операции или времени чтения сообщения. Пока операция не завершена, показывать честное статическое состояние ожидания.
- При повторном действии отменить или перенаправить текущий переход к новому состоянию. Не ставить клики в очередь анимаций.
- Предпочтительны transform и opacity. Изменение цвета может быть мгновенным либо через opacity-слой. Размеры, положение в потоке, тени, filter и blur не анимировать.
- Начальное содержимое страницы не скрывать до окончания скрипта. Не делать массовые reveal при каждом переходе.

## Длительности и easing

Источник: [tokens.css](../../tokens.css). Вход `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)`, выход `--ease-in: cubic-bezier(0.7, 0, 0.84, 0)`, симметричное изменение `--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1)`.

Использовать tween с точной длительностью. Не выбирать physics spring по умолчанию: `visualDuration: 0.8` не означает полное окончание за 800 мс. Отскок и overshoot не нужны. CSS принимает миллисекунды; Motion принимает duration в секундах, например 440 мс соответствует 0.44. Не передавать 440 как секунды.

Stagger нужен редко: максимум четыре элемента, задержка 40 мс, переход 320 мс, вся группа 440 мс. Новые данные доступны сразу; чтение не зависит от окончания последовательности. Для длинных списков stagger не используется.

## CSS и Motion

Простая смена opacity/transform по состоянию: CSS. Прерываемый составной переход, согласованный вход/выход и сохранение элемента до exit: Motion, если это подходит выбранному стеку. Сначала проверить зависимости и актуальный API через подключённый Motion-плагин.

При React использовать `motion/react`, клиентскую изоляцию интерактивных частей и reduced motion API. При другом стеке выбрать соответствующий публичный API. Это условные рекомендации, а не выбор React. Не подключать одновременно Motion, GSAP и другие движки для одной задачи. Не добавлять платные пакеты ради обычного fade.

Не держать координаты указателя или прогресс каждого кадра в React state. Подписки, таймеры и animation handles очищаются при смене состояния и unmount. `will-change` только при измеренной пользе, на время движения. Не анимировать один transform двумя системами.

## Загрузка, данные и доступность

Skeleton статичен и совпадает по геометрии с результатом. Короткую загрузку не растягивать искусственно ради индикатора. Для длительной работы показать текст и реальный прогресс, если он известен. Бесконечные вращения, shimmer, пульсирующие точки и анимированный счёт чисел не предусмотрены.

При prefers-reduced-motion убрать все перемещения, scale, stagger и декоративное движение. Допустим только opacity до 100 мс; фокус, переключатели и ошибки мгновенные. Не оставлять элемент в opacity 0 из-за отсутствующей анимации. Уменьшение длительности без удаления transform не считается выполнением этого правила.

Ручная проверка в будущей реализации: быстро открыть/закрыть панель, переключить вкладки несколько раз, сменить маршрут во время загрузки, включить reduced motion. Финальное состояние, фокус и доступность должны совпасть с последним действием.

## Стабильность переключения вкладок

Переход между любыми вкладками плавный: одновременное исчезновение прежней панели и появление новой за 440 мс, без задержки действия; при reduced motion только opacity до 100 мс. Вес шрифта, размер, межстрочный интервал, отступы и границы названий одинаковы во всех состояниях, чтобы текст не дёргался. Активность показывают цвет и плавное появление индикатора. Повторные переключения прерывают текущий переход; доступность и фокус обновляются сразу.

В статической витрине панели занимают одну ячейку CSS Grid: высота определяется самой высокой панелью, не меняется при переключении. Неактивная панель сразу получает inert и aria-hidden; после затухания скрывается через visibility. Не анимировать размеры контейнера.

По последнему уточнению пользователя длительности обычных переходов удвоены относительно исходной системы: 160 / 240 / 320 / 440 / 560 / 640 / 800 мс. Предыдущий предел 400 мс заменён на 800 мс. Задержки наведения, сетевого ожидания и таймеры уведомлений не удваивать. Обратная связь начинается сразу; фокус и доступность меняются мгновенно. Reduced motion остаётся до 100 мс.
