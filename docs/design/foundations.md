# Визуальные основы

## Образ и иерархия

Спокойная рабочая среда: плотный графит, холодные поверхности, чёткая типографика, небольшие синие акценты. Отличительный знак бренда находится в навигации, а не повторяется как декор. Разделы различаются содержимым и композицией, сохраняя общие размеры и поведение.

Главный приоритет экрана: название задачи → состояние → действие → детали. Заголовки выровнены влево. Не использовать крупные маркетинговые обещания, фотографии, декоративные цифры или одинаковые тройки карточек. Однородные строки данных, наоборот, должны иметь одинаковую структуру: правила разнообразия лендингов к таблицам не относятся.

## Палитра

Синий `#2878C8` на графите имеет контраст около 3,50:1: подходит для значимой графики, но не для обычного мелкого текста. Ледяной `#DCE6ED` не подходит как текст на синей кнопке (3,60:1). Белый на синем даёт 4,55:1: не снижать непрозрачность текста или кнопки в активном состоянии. Подробнее в [проверке контраста](verification.md).

### Состояния

| Состояние | Текст / фон светлой темы | Текст / фон тёмной темы |
| --- | --- | --- |
| Успех | `#18794E` / `#E7F4ED` | `#8DE1B5` / `#17392F` |
| Внимание | `#885A12` / `#FFF4DE` | `#F2CC88` / `#4A3A22` |
| Ошибка | `#B53842` / `#FCECEF` | `#FFB0B8` / `#572B35` |

Семантический цвет всегда сопровождает текст или значимую иконку. Тёплые поверхности предупреждения используются только для сообщения, не для оформления страницы. Не красить весь экран из-за одной ошибки. Нейтральное состояние не выдавать за успешное.

## Темы

Системная настройка применяется при отсутствии сохранённого ручного выбора. Ручной выбор «Светлая / Тёмная / Как в системе» управляет одним корневым `data-theme`. При режиме «Как в системе» не фиксировать светлое или тёмное значение. Не делать вложенные переключения тем внутри рабочих экранов.

Применить тему до первого заметного кадра. Не анимировать весь документ при переключении. На тёмных поверхностях глубину выражать светлотой и границей; тень допустима только для перекрывающих слоёв. Отдельно проверять логотип, disabled, фокус и сообщения в обеих темах.

## Типографика

| Стиль | Семейство, вес | Размер / интерлиньяж |
| --- | --- | --- |
| Текст логотипа YETI STREAM | Nunito Sans ExtraBold 800 | Референс 28/35 px; размер адаптируется вместе со знаком |
| Название страницы | Manrope 700 | 32/40 px, на узком экране 24/30 px |
| Название раздела | Manrope 600 | 20/25 px |

| Основной текст / поле | IBM Plex Sans 400 | 16/24 px |
| Кнопка / label | IBM Plex Sans 500 | 14/20 px; поля на мобильном не менее 16 px |
| Таблица / метаданные | IBM Plex Sans 400/500 | 14/20 px |
| Редкая вторичная подпись | IBM Plex Sans 400 | 12/18 px, без критических условий |

Цифры в таблицах и суммах используют tabular-nums. Не добавлять отдельный загружаемый шрифт ради чисел. Система использует три семейства: Nunito Sans только для надписи логотипа, Manrope для заголовков, IBM Plex Sans для интерфейса. Моноширинный системный fallback допустим только для технических идентификаторов и кода. Заголовки прямые, без курсива и CAPS; написание YETI STREAM является исключением для бренда. В обычном тексте и логотипе tracking 0; заголовки допускают -0,02em.

Сохранять кириллицу, `ё`, знак рубля, проценты и длинные имена. Nunito Sans, Manrope и IBM Plex Sans имеют кириллические наборы и OFL-лицензию; [источники](sources.md). При реализации размещать WOFF2 локально, сохранить лицензии, использовать font-display: swap и согласовать метрики fallback. Для Nunito Sans загружать только нужное логотипу начертание 800. Шрифты встроены в визуальный лист и размещены локально для HTML-стенда; рабочие font assets приложения ещё не созданы.

## Размеры и сетка

- Базовый шаг 4 px; шкала 4, 8, 12, 16, 20, 24, 32, 40, 48, 64 px.
- Минимальная активная область 44 × 44 CSS px; визуальная иконка может быть меньше. Между соседними маленькими целями оставлять 8 px, не перекрывать их псевдоэлементами.
- Sidebar 240 px; header 64 px. Ширина контента до 1280 px, рабочая таблица при необходимости до 1440 px. Форма до 640 px.
- Поля страницы: 16 px до 768 px, 24 px от 768 px, 32 px от 1280 px. Между разделами 32 px, внутри группы 16 px, label и control разделяют 8 px.
- На ширине от 1024 px sidebar видим; ниже используется кнопка «Меню» и боковая панель. На 768-1023 px вторичные колонки остаются только если помещаются без сжатия полей.
- Мобильная сетка одноколоночная. На широком экране форма и итог используют соотношение 2:1, список и детали 3:2; треки `minmax(0, ...)`.
- Радиус поля, кнопки, вкладки, тултипа 8 px; панели 12 px; диалога 16 px. Pill только для компактного статуса, не для всех кнопок.
- Высота кнопки и соседнего поля одинакова, минимум 44 px. На сенсорном интерфейсе допустим вариант 48 px.
- Слои: базовый 0, sticky 10, menu 20, backdrop 30, dialog 40, toast 50, tooltip 60. Внутри модального top layer использовать портал в доступный контекст диалога, а не пытаться исправить всё большим z-index.

## Логотип и иконки

Исходник [logo.svg](../../logo.svg) имеет квадратную область и три цвета бренда, а также белые детали. Сохранять viewBox, пропорции и пути. На графитовом фоне часть тёмного силуэта теряется; использовать светлую подложку `--color-palette-light-surface`.

Предлагаемое размещение: знак 40 × 40 px внутри подложки 56 × 56 px, свободное поле 8 px; рядом текст YETI STREAM в Nunito Sans ExtraBold 800, прямое начертание, нормальная ширина и tracking 0. Использовать токены `--font-wordmark` и `--font-weight-wordmark`; не подменять 800 синтетическим bold (`font-synthesis: none`) и не растягивать буквы transform. При нехватке места сохранять знак и доступное имя. Не анимировать маскота и не использовать его вместо индикатора загрузки. Малые размеры 24/32 px проверить отдельно перед созданием favicon.

Phosphor Regular: 16 px в компактных строках, 20 px у действий, 24 px в крупных элементах. Не менять stroke вручную для каждой иконки. Примеры смыслов: список заказов, каталог, настройки, копирование, проверка, предупреждение, закрытие. Точные экспортируемые имена проверить в установленной версии будущей библиотеки. `?` можно отображать текстовым глифом внутри собственного компонента справки.

## Доступность и адаптация

Цель WCAG 2.2 AA. Контраст обычного текста ≥4,5:1, значимой графики и границ ≥3:1. Проектная цель для основных текстов выше минимальной. Разделители `--color-line` декоративные и не заменяют контрастную границу управления.

Фокус: outline 2 px, offset 2 px, появляется мгновенно; пространство между кнопкой и кольцом заполняется текущей поверхностью. Проверять фактические соседние цвета. Не закрывать фокус sticky-панелями. Заголовки последовательные, есть skip-link, main и подписанные области навигации.

Проверять 320 / 375 / 414 / 768 / 1024 / 1440 px, увеличение текста и zoom. Длинные ссылки переносятся, поля не выталкивают сетку. Кнопки переносятся как целые элементы; при увеличении текста допускается рост высоты, без обрезки подписи. Не скрывать смысловые данные через overflow-x: clip ради формального отсутствия прокрутки.

## Начало загрузки шрифтов

Шрифты, используемые на странице, начинать загружать сразу: объявлять локальные @font-face в раннем CSS и preload нужных начертаний в head до основных стилей (as="font", правильный MIME и crossorigin). URL preload должен точно совпадать с URL в @font-face, чтобы не загружать файл дважды. Не откладывать загрузку шрифтов до прокрутки, клика, переключения вкладки или запуска JavaScript. Сохранять font-display: swap и читаемый fallback; не скрывать страницу в ожидании document.fonts.ready. Ранняя загрузка не гарантирует мгновенную готовность на медленной сети.

В HTML-стенде preload включён для всех шести демонстрируемых начертаний: IBM Plex Sans 400/500/600, Manrope 600/700 и Nunito Sans 800. В будущем приложении список ограничивается начертаниями текущей страницы, без загрузки ресурсов других маршрутов.
