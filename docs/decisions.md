# Решения и открытые вопросы

Дата: 1 ноября 2026 года. Этот документ не разрешает реализацию перечисленных возможностей автоматически.

| ID | Решение |

| U02 | Корневые зоны: `/`, `/app`, `/admin`, `/partners`; `/` пока пусто. |

| U06 | Пока не писать автотесты; проверять затронутый сценарий после реализации или при ошибке. |

| U09 | Подтверждено в уточнении: владельцы стриминговых каналов, выбор / настройка / отслеживание заказа, сдержанный технологичный тон. |

## Принятые проектные решения

| ID | Выбор | Причина |
| --- | --- | --- |
| D01 | Название YETI STREAM | Взято из title исходного logo.svg; написание можно уточнить отдельно |
| D02 | Собственная тема «Графит и лёд» | Сохраняет бренд, поддерживает повседневную работу |
| D03 | Светлая и тёмная темы, выбор по системе | Паритет контраста и удобства; графитовая версия референсная |
| D04 | Manrope + IBM Plex Sans | Различимые заголовки, читаемый интерфейс, подтверждённая кириллица |
| D05 | Phosphor Regular | Единая линейная семья, без смешения библиотек |
| D06 | Sidebar на широком экране, меню на узком | Стабильная навигация для трёх рабочих зон |
| D07 | 44 px элементы, шаг 4 px, радиусы 8/12/16 px | Предсказуемость и доступность касаний |
| D08 | Длительности 80-400 мс; без физических spring по умолчанию | Жёсткий верхний предел времени; visualDuration не гарантирует окончание spring |
| D09 | `?`: hover 240 мс + fade 120 мс, focus/tap без задержки | Итог 360 мс соответствует U04; переопределяет длинную задержку из общих навыков |
| D10 | Контраст считать по конкретной паре цветов | Брендовый синий не подходит как мелкий текст на всех поверхностях |
| D11 | tokens.css как единый источник значений | Исключает ручное расхождение экспортов |
| D12 | Статический визуальный лист, без интерактивного прототипа | Делает спецификацию обозримой внутри текущего объёма |

Проектные решения D01-D12 являются рабочей базой, выбранной в рамках поручения. Они не выдаются за отдельное пользовательское утверждение каждой детали. Изменять их согласованно с документацией, а не локально в одной странице.

Не задавать все вопросы одновременно. Поднимать только блокирующие текущую задачу. До ответа не придумывать бизнес-числа и правила; продолжать независимую часть работы.

## Как обновлять решения

Указать дату, ID, новое решение, причину и затронутые документы. Изменить канонический источник, затем связанные спецификации. Историческую причину сохранять только если она объясняет действующее ограничение. При смене этапа отдельно обновить ограничение «только документация»; запрет автотестов не снимается автоматически.
